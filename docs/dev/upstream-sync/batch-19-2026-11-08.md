对应#14，与P13共用输出链。`data/export/ExportHooks.kt` 的泛型 `rememberExporter` 唯一消费者是

1. 专用入口 `prepareModeInjectionExport(snapshot: PromptInjection.ModeInjection)` 捕获点击时的不可变用户模式注入；
   服务调用原 `ModeInjectionSerializer`，固定application/json。该数据来自共享用户设置，无企业文件或附件授权，
   不为此增加公开的任意正文／Static来源／空校验回调入口。纯序列化仍在data/export，ImporterState不随本项重构。
2. 服务发出不透明 `PreparedExport` 句柄，只公开名称、MIME和状态；内部保留固定内容或本次临时payload、
   明确来源及Pending/Claimed/Closed状态。PromptVM持句柄和显示状态，UI保留launcher；不把正文／路径放Bundle，
   不另建ID到payload的全局表。准备失败不打开选择器，连续点击不覆盖正在等待的请求。
3. 返回CreateDocument目标后由同一服务一次性claim，打开流、write/flush/close全部成功后才回成功回执；
   null stream是带稳定reason的失败。新API显式接收仅此CreateDocument流程签发的目标，不能将任意已有URI当可删除对象。
   未开始写入前也已拥有此次目标的补偿责任；回调使用立即进入try/finally的结构化协程交接，覆盖scope已取消的情况。
4. 选择器取消、启动失败、页面真正退出、重复／过期回调分别discard或拒绝；旋转由既有PromptVM保留pending句柄，
   不释放后再偷偷生成新请求。进程死亡回调找不到句柄时报告request_expired并清理本次新建目标，不静默留下空文件。
5. SAF写入与失败清理复用 `MediaExportService.saveTextDocument` 的核心，扩展为私有输出操作供两种payload使用；
   既有RichTextHost调用仍保留，不扩大成全项目导出框架。取消先重抛，finally仅清本操作新建目标及未发布payload，
   已取得所有权的必要清理可用NonCancellable，清理异常作为原错误suppressed，不能用日志代替失败回执。
6. 分享复用现有 `publishFile`：启动失败删除候选，URI成功交付后按现有临时文件协议保留，不能sheet关闭就删除。
   原hook的建文件／直接writeToUri／FileProvider／分享Intent路径退役；唯一消费者迁移后删除失用的泛型ExporterState/rememberExporter，
   保留仍被导入与纯序列化消费的接口。旧cache/export只纳入 `MeasixPilotApp.retireApplicationTempFiles` 既有临时目录清单，
   不新增恢复阶段或碰Artifact目录，启动清理也不等于定时TTL。

准备阶段的candidate放服务外层try/finally，覆盖所有withContext；IO完成但返回时取消仍由服务清理，不能让文件只存在于IO lambda里。

局部finally覆盖“已拿句柄但尚未接纳”，不新增第二套发布确认协议。
`onCleared`不能向已取消的viewModelScope启动discard：服务提供非挂起、幂等release，先让Pending句柄失效并取得私有payload清理责任，

页面存活时清理失败并入原回执，页面退出后保留完整日志及未完成清理证据，由原启动临时目录退役重试，不能报成功。

### P14 模型请求图片编码：算法、授权与派生缓存分离

对应#41。采用同进程重复图片减少解码／缩放／WebP编码的目标，保留2560边长、16M像素上限、WebP Q90、alpha、EXIF与原图策略。
**撤回初稿中“ArtifactStore负责模型编码”和“请求URL→预编码表”的设计。**
同一附件可以同时出现在普通USER图片和MCP原图结果中，URL及源身份相同但policy不同；URL表会污染原图或拒绝合法请求。
Responses还可能直接回放opaque原始输出，预扫描会编码实际不会发送的图片，改变失败和费用准入时机。

#### 最终组件分工

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| `ArtifactStore`／`ArtifactReadLease` | 现有retain、冻结文件授权、受pin保护的源读取和引用生命周期 | 不新增WebP策略、模型缓存、反向模型依赖或第二删除协议 |
| 新增app `data/ai/attachments/ModelRequestImageEncoder` | 将原RealmAccess／read lease与请求关联，经Session owner复验，管理可丢弃内存编码缓存，调用ai纯编码 | 不写Artifact／消息／上下文，不发Provider请求、不选择模型 |
| ai `RequestImageEncoder` 窄接口与 `FileEncoder` | suspend编码能力；纯像素算法、明确policy、bytes+MIME及base64包装 | 不持Settings／RealmAccess／DAO／Store，不管理应用Session |
| `StepRunner.generateInternal` | 在原准入链内创建并关闭本次编码能力，保证read lease覆盖完整Provider流 | 不预扫描所有消息生成URL表，不把派生bytes写回历史 |
| 四协议adapter | 在实际需要image block时按当前part调用编码能力，保持各自wire/replay | 不用缓存判断授权，不从当前空间获取资源 |

#### 调用时序与取消

1. 既有顺序保持：retainForRequest→transformers→`admission.admit`（RequestAssembler及authorized files校验）→
   `modelRequests.execute`取得原模型准入→`admission.requireReadable`/read lease检查→创建请求编码能力→Provider构造与完整流收集。
   通过 `TextGenerationParams` 的 `@Transient` 可选能力传给adapter；不改变providerVisibleMessages、token估算、receipt和接纳事务。
2. app能力绑定原RealmAccess、ArtifactReadLease；每次encode先检查自身未关闭、协程active，并通过既有 `EnterpriseSessionController.withRealmAccess(originalAccess) { Unit }` 做短授权检查，
   file URI只能由该lease的resolveUri/file取得，不用当前Settings／当前空间重签。命中返回前及编码后再做同一短校验；
   不用withSelectedRealmAccess把切页误作运行域变更，不把整个编码放在Session锁内。
   finally先关闭该能力，再由外层use释放read lease；close幂等，关闭后调用明确失败，不能fallback裸文件读取。
   `admission.requireReadable` 维持StepRunner原调用位置；它会读取配置与记忆权限，不为每张图片重复执行或重新对账上下文。
3. 四adapter图像构造链改为suspend并传递同一能力，不在builder内另开Job：
   Chat Completions的buildMessages/assistant/non-assistant/tool content→encodeChatImage；
   Responses的buildMessages/assistant/user/function output/content→encodeResponseImage；
   Claude的buildMessages/assistant/user→toContentBlock/toToolResultBlock；Google的buildContents/model/user→toGooglePart/toFunctionResponsePart。
   JSON DSL先await叶结果再put/add；响应解析链不改，Responses opaque replay分支不触发编码。
4. 统一native image入口为suspend，替换四adapter旧非挂起调用，删除失去消费者的旧旁路。
   图像encodeBase64的runCatching改显式try/catch，CancellationException原样传播，不能被getOrElse包装失败；音视频不借机重构。
   hash循环、原图base64及编码前后检查active；Bitmap.compress不可抢占，停止等待其返回并完成Bitmap清理再退出，不能用NonCancellable包整个编码。
5. 无应用能力的ai独立调用走同一纯无缓存算法；app主／子Turn必须提供能力。已提供能力但拒绝或失败时绝不回退。
   ModelExecutionService／ModelExecutionLease／ModelRequests继续只负责模型准入，不增加图片扫描职责；
   标题、建议、摘要实际为文本，附件检查已有授权bytes→data URI链，本批不为它们加第二编码入口或承诺缓存复用。

#### 缓存键、内存与生命周期

- 每次先完成源授权，再对原lease保护的已发布不可变payload流式计算SHA-256；key为原域/Session namespace＋内容摘要＋完整静态编码policy
  （实际MIME、算法版本、格式、尺寸／像素上限、质量及原图处理决定）。不同来源同内容在同域同Session可复用；
  无需为缓存暴露Artifact数据库ID或新增路径索引。withPrefix只影响最终base64包装，不保留两份二进制。
- 只缓存实际生成的静态派生bytes+MIME，总计64MiB、按ByteArray实际size的LRU；超大单项只服务本请求、不入缓存。
  不保留Bitmap或base64字符串，不新增磁盘文件、Artifact记录、schema或备份；只承诺未淘汰的同进程命中。
- 用一个suspend Mutex串行处理miss后的再检查、解码/编码和发布，最多一张静态图正在解码；同key自然合并。
  不新增per-key锁表、共享Deferred、等待者计数或脱离请求的编码Job。等待可取消；持锁请求取消后退出，下一请求自行重新检查／计算。
  所有Session／Artifact挂起校验放缓存锁外，锁内只检查closed/active/内存代次并编码；释放锁后复验授权再交付。
  不持Artifact／Session锁等待缓存锁或编码，也不在缓存锁内取得领域锁。
- 每次命中仍需原读租约与原授权。新请求重新retain时源缺失就拒绝，不让缓存复活已删源；已签发read lease的冻结读取权和pin
  沿原合同可完成读取，不因本次优化改造成即时撤销的数据库视图。真实Session撤权和请求取消仍由原admission／父worker处理。
- 清理在模型输入组件内消费现有ArtifactStore.lifecycleChanges与EnterpriseSessionController.state，以单一受app生命周期管理的观察订阅
  对失效源／退出／重置保守清空相关namespace并推进内存代次（个人源重置由Artifact生命周期变化覆盖）；
  收到失效先原子递增代次，再于领域锁外等待缓存锁清理；发布比较捕获代次，禁止迟到回填。该维护可丢弃缓存，不作授权证明，不让ArtifactStore回调模型编码器或新增恢复阶段。
  Personal使用原个人namespace及重置代次，Enterprise使用完整原scope与Session身份；切换页面不换成新主体。
  订阅只做缓存维护，不调度编码；编码仍归原请求协程，观察器销毁即清空缓存，不影响已合法交付的请求引用。
- GIF原样；MCP preserveOriginal对jpeg/png/webp/gif原样，均绕过静态缓存。HEIC即使标preserveOriginal仍按既有策略生成WebP，
  不突然转发协议未接受的格式。外部http/data与非托管可变URI保持原处理且不跨请求缓存；受管路径准备失败不得旁路重读。

验证：同Session多轮/工具Step只编码一次，USER与MCP同URL不同policy不互相污染；Responses opaque replay不调用encoder；
四协议真实MIME/base64、GIF/HEIC/alpha/EXIF保持；同路径等长同mtime内容变更miss，不同域/Session不命中；
新请求源已删、原Session撤权、能力关闭后拒绝；已签发合法read lease保全；排队取消、编码中取消、清空并发迟到发布、LRU/超大单项。
沿现有FileEncoderExifTransformTest、四线message/stream测试、Turn请求准入测试增加必要行为断言，新增模型图片编码组件测试。
设备测冷热CPU、准备耗时、分配与堆峰值，计入活动请求/编码临时内存，64MiB不是进程内存上限；不凭命中数宣称性能达标。
