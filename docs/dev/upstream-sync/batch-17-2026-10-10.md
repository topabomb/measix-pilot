## 4. 详细实施顺序

### P01：依赖的窄范围升级

升级 Kotlin 到 2.4.20、core-ktx 到 1.19.1；Haze 从本地 alpha05 到上游最终稳定 2.0.1 时核对现用 blur/style API，
三件套 haze／haze-blur／haze-blur-material3 同步升级，必要适配仅限其当前消费者。核对 API<31 的 RenderScript 首帧／滚动、detach 和弹层 capture；高 API 模拟器不能代替此项。
保留 AGP9 optimization、keep rules、双 ABI、Debug 后缀与 Bundle splits 规则。
核对 Maven 来源、许可证和依赖树；不照搬上游所有依赖、native 模块或对 overscroll 的视觉改动。

### P02：MCP 宽 schema 解析

SDK 切换到上游最终 `0.15.0-rikka.4`，来源固定 `7303e3cbb7c19aeaa46712839b5e5bd9d6cbacd5`；官方 0.15.0 基线
`76b8e7d63aac39fe41e03684e3b91a6c3724a8da` 之后有 76 个提交，并非只有 schema 修复。核对制品来源、依赖及 Apache/MIT NOTICE；CC-BY 文档不混作代码许可证。
在原唯一 client 工厂显式选择 `ProtocolEra.Legacy`，避免新默认 Auto 对自有 SSE transport 错误探测现代协议；不宣称新增协议支持。
原工具发现仍由同一个 SDK request ID 管理超时、取消、分页和响应，保留完整原始 Tool 的 wire capture；不增加裸 HTTP tools/list 旁路或 schema 占位改写。
`McpCatalogStore` 仍是已确认目录 owner，定义 hash 使用原始完整 Tool。有效但非 SDK 简化类型的 inputSchema 不阻断全目录；
真正畸形的 Tool／分页／重复名称仍保留诊断、旧目录与失败重试，不能跳过坏项伪装成功。
核对 `structuredContent` 的任意合法 JSON 形态贯通本地工具结果，不强制转对象或丢掉 scalar／array。
保留 16MiB wire 上限；验证 type 为数组、null、额外 schema 字段、$defs/$ref、structuredContent、分页、取消、并发 request ID 和目录失败保全。
真实 SDK fixture 断言不发送 server/discover，也不进入新协议 inputRequired 自动交互回合。

### P03：OAuth 发现、回调与 resource

仅个人 MCP OAuth 路径适配，企业 Session／凭据协议不变。新动态注册使用 localhost，已有或手动 clientId 保持旧 IP 回调；
在原 OAuth 状态新增回调 host 策略，缺字段为旧 IP，注册后严格复用，不能遇任意 403 就换地址重新注册。
listener 继续绑定 loopback 和临时端口，localhost 的 IPv4／IPv6 解析和 listener 必须一致，
授权请求固定本次 redirect URI 与 state，浏览器启动失败、取消、超时及成功均等待 listener 实际退出。
元数据读取区分 404 等“未提供”与连接、认证、JSON 错误；只有前者允许继续原 server origin 的授权服务器发现，
不能吞异常降级。只规范化根路径的 host 与 host/，非根路径尾斜杠、query 和 percent-escape 不视作相同 audience；拒绝 fragment／userinfo。
原 OAuth 状态保存授权时 resource 并用于 refresh；旧状态缺字段按旧算法恢复原值，不能把已有 token 静默重标为新 canonical resource。
新授权才使用新规范身份；不同资源必须重新授权，迁移失败保留诊断。
不提供虚假的 CIMD URL；仍使用已配置 client ID／可审计动态注册。身份变化后的远端回执不能提交旧凭据。

### P04：Provider 请求头

在现有用户 Provider 定义及 typed 编辑 contract 中增加默认空 headers，旧持久化缺字段通过明确配置读取／迁移边界保持原行为。
先应用 Provider headers，再应用 Model request headers；规定同名头大小写不敏感且覆盖结果唯一。
文本、标题／摘要、图像、模型列表、embedding 和余额查询复用各自既有请求构造入口，不在 UI 网络调用。
Provider 类型转换、复制、导入／备份及 providerOverwrite 都保留 headers。原 Turn 捕获 wire，重试不得读取新编辑值；
余额缓存身份纳入影响请求的头。受管请求的认证／关联保留头不可被用户覆盖，也不把用户字段写入企业发布定义。
失败保留完整脱敏诊断，五语编辑说明随实现更新。

### P05：图像请求修复

修复 OpenAI-compatible 自定义 size 被误删，以精确 host 而非包含字符串区分真实官方服务，保留 auto 语义。
OpenRouter 按[官方 image API](https://openrouter.ai/docs/guides/overview/multimodal/image-generation) 使用 POST `/api/v1/images`，
生成与编辑共用该端点，编辑用 input_references，解析 media_type；按原 OpenAIEndpointProfile 精确 host／baseURL 前缀构造，失败不换端点重试以免双扣费。
本地 `ImageGenerationCoordinator` 和 `GeneratedMediaStore` 保留 scope、原 Session、取消、临时 payload 与发布交接。
多斜杠模型名继续使用原 UUID payload 命名；测试验证实际 URL、JSON／multipart、失败诊断和旧配置兼容。

### P06：连续分叉命名

只扩 `ConversationTitleCoordinator.createForkWithTitle` 的名称计算，保留串行锁和 durable create 回执。
末尾 `(N)` 从 N+1 查找空闲名称，非数字括号保持原文；处理超大数字与整数溢出，不能循环或变负。
不改变自动标题 token／手动标题 CAS，不把新名称提前发布。现有并发与失败测试扩充连续分叉场景。

### P07：聊天导出选项

将 ImageExportOptions 收敛为同时服务 Markdown 和图片的选项，“包含思考过程”默认开，关时禁用展开选项。
输出仅过滤 Reasoning，不过滤工具、附件和普通回答；Markdown 多行推理逐行引用，图片前一消息按下标关联。
保留 `MediaExportService` 的访问复验、离屏组合树取消清理、Bitmap 回收与失败弹层；成功仅在交付后提示。
移除旧命名和无调用路径，同步五语及消息渲染参考。导出不是改写历史或自动隐藏后续导出内容。

### P08：原生图表工具

沿 `LocalTool`／工具装配、纯参数校验、执行结果与 `ToolLivePhase` 接入 `chart_display`，默认不启用。
共享唯一 validated spec，限制图表类型、系列／点数、有限数值、标签及总 payload，支持折线、柱状、散点及表格查看。
纯验证先于审批；图表不执行脚本、不读取网络或文件，不把输入存在当成功。成功结果由原 Turn checkpoint 保存，
渲染与图片导出只消费 typed completed／resultStatus 成功的已提交投影；拒绝、运行中和畸形历史保留通用工具详情。
图和表共享 validated spec，tick 数量有上限；log 轴拒绝非正值，柱状图只支持 linear 并使用明确零基线，不能按极小区间夸大差异。
失败显示原工具诊断。图表使用 app 内原生 Canvas，不增加只有一处消费者的 ui module。
为小而有界的图表结果明确工具输出保留策略；旧助手不自动获新工具，企业仍需现有许可和发布支持。

### P09：保留历史的手动摘要检查点

保留外层 `ConversationContextPayload` v2 和 v1/v2 读取，在 `ConversationContextSource.HistorySummary` 增加
`checkpoint: HistorySummaryCheckpoint? = null`，检查点自身 version=1。记录覆盖原始历史前缀的有序
`ContextMessageLocator`（node/variant）、语义内容指纹及前一检查点 entry 身份；不从当前 Settings 重建历史。
指纹覆盖模型可见正文／工具内容及来源，排除时间、用量等显示更新；同 ID 内容修改也会使检查点失效。

一次摘要的分块结果依原顺序合并成一个摘要节点，由新 `InsertHistorySummaryCheckpoint` 命令和来源在同一会话事务提交，
插在覆盖前缀之后、保留尾部之前。保持原 auxiliary worker／Session 归属及 snapshot CAS；生成期间分支、正文、来源改变，
或会话开始运行／等待工具交互时拒绝迟到提交并保留原历史。旧节点、Turn／Tool、子助手关系、FTS、附件引用均保留，
移除只供旧摘要调用的 destructive ReplaceMessageTree／commitSummary 路径，其他合法消费者按实际用途保留。

`RequestContextPlanner` 在当前分支校验有序覆盖前缀及依赖，选最新适用检查点，以摘要加未覆盖消息构建新请求，再应用 disclosure 对账。
历史窗口只裁未覆盖尾部，选中摘要始终保留，不能对摘要加尾部整体 limit 而丢掉摘要。
所有检查点容器先从普通用户消息候选中排除，失效摘要不能因来源 entry 不适用而作为 USER 正文漏出。
`TurnRequestAdmission` 为本次选中摘要登记 `MessageOrigin` use，沿原 `conversation_history_summary` 应用封装发送；
过去的 admission 不补写 use，也不因后来的摘要重算已接纳请求。保留尾部只在完整 USER 轮次边界切分。

重复摘要读取前一有效摘要全文加新增覆盖区间，不能把前一摘要按普通消息 2000 字符截断；新检查点仍保存原始覆盖前缀和前一依赖。
编辑覆盖区、切换兄弟 variant、删除后重新校验；结构合法但覆盖项缺失仅判失效，结构非法仍报告完整性错误。
摘要正文编辑建立新 variant／应用来源并继承该摘要覆盖描述，不能变成真实用户指令；删除摘要删除整个节点及其来源，
不得回选旧 variant 复活该摘要。fingerprint 与 locator 身份分开规范化，fork 先验证原指纹，仅重映射明确身份字段及 entry 依赖；
不能重新 hash 克隆后的正文而把原失效摘要修成有效，附件路径／工具结果等语义变化仍使摘要失效，缺失依赖保持失效。
旧缺 checkpoint 字段保持 legacy 摘要语义，不补造覆盖范围或复原已删除正文；备份和 JSON codec 按可选字段兼容。
同次更新数据与请求上下文参考；设备验证事务失败、关闭重开、个人备份／企业保全及新旧 schema 同构。

### P10：生成模型显示信息保全

在 START 创建 Assistant variant 时从已捕获模型保存 immutable 显示信息，至少包含原 wire model ID 与 displayName。
该值跟随消息保存、复制和 fork；编辑正文保留，重新生成新 variant 则捕获新模型。现有历史缺字段明确 unknown，
不得用当前可变设置回填“当时模型”。UI、导出、消息详情和子助手使用同一显示投影，执行／诊断设置入口仍按真实 reference 授权。
序列化兼容边界及必要 Room migration 与 P09 一起核验，不为显示字段另建 Store 或第二模型定义。

### P11：模型组折叠

在现有 `ModelListState`／原配置查询组身份上维护折叠，偏好由 Settings typed command 保存，不写查询投影。
个人 Provider 与企业组按原域和稳定身份区分，不能只按显示名称或列表下标；搜索有命中时临时展开，不改持久选择。
折叠不影响 favorites、当前模型和模型准入；等待保存期间切域不能把旧操作写到新域。缺字段默认展开，重开保留，失败可诊断。

### P12：会话创建时间排序

增加明确的显示排序偏好，默认更新时间以保持旧行为。`ConversationQueryService`／Repository／DAO 在 scope 和原过滤条件内
按创建或更新时间排序，再做分页／限额；置顶优先并以稳定 ID 处理相同时间。抽屉、历史及文件夹保持一致，
“最近会话”业务查询不受用户列表排序改变。既有 create_at 无需回填；必要索引通过实体及显式 migration 同步创建，
抽屉日期分组也按所选时间字段；切换排序取消旧 Paging 流并重新查询，不对已有一页内存重排。
核对升级与新安装 schema，并以真实 SQL 查询计划、不同域／文件夹和多页数据验证。

### P13：Settings 消费与解码

LocalSettings 改为跟踪实际读取的 CompositionLocal；`userDocuments` 的解码及昂贵派生放后台，保持唯一观察和当前 writer。
不能以 initial dummy 当恢复完成，`initializeForRecovery` 仍暴露读取、迁移和解析错误，取消关闭门禁。
将 `BingLocalOptions` 修正为符合值语义的相等性；launchCount 继续保留原 canonical internalState，不另建可写缓存。
新安装同样经过旧 Preferences 读取边界；缺少 MODE_INJECTIONS 时采用明确构造默认，显式 `[]` 保持空；覆盖新装、历史缺字段和用户主动清空，
不能对已迁移的明确空列表重灌默认。清理产生假变化的默认值仅针对实际字段，不发布内存先行状态。
用现有 SettingsStartup／恢复测试补关键 observer 和错误边界，局部重组不靠不稳定耗时断言。

### P14：现有界面可靠性

JsonTree 弹层使用自己的选择容器；日志复制捕获具体异常、保留可展开／复制的诊断，不截掉正文或谎报成功。
搜索服务商子页返回应回主选择页，再次返回才关闭；在窄屏 Sheet 和宽屏 Dialog 都验证，必要使用原 AdaptiveModal 的 dismiss 语义，
不能假定 BackHandler 可覆盖 Dialog 原生返回。搜索卡无法解析的历史／归档结果使用原工具详情，不显示伪造空搜索结果。
输入底部遮罩使用原背景与实际 IME 边界，核对 AMOLED、背景图、普通无背景及键盘显隐，不新增滚动意图或重复 inset。

### P15：图像快捷入口

按 Pilot 包名注册 shortcut/action，通过原路由等待恢复并进入正式 ImageGen 页面；冷启动和 onNewIntent 一致。
不自动生成、不选新模型、不重新解释失效企业引用。复用现有标题资源／图标体系，不新增另一图片生成页面。

### P16：Rootfs／shell 能力

按 RootfsCompatibility 的真实可执行文件及镜像架构验证 Alpine/BusyBox 与既有 bash rootfs，不能只凭 `/bin/sh` symlink 判定可运行。
tar 的 `.`／`./` 根目录条目允许跳过，非目录空路径仍拒绝；保持原 staged 安装、安全路径／链接、ELF 与页大小检查。
Workspace 执行和交互 PTY 复用同一 launch specification；shell 启动参数、PATH、环境及发行版提示同步更新。
System 工作区提示在 START 捕获实际 distro/shell，不按“Linux=Ubuntu/bash”硬编码，也不把镜像输入伪装成用户指令。
准备匹配 x86_64 的官方 Alpine 镜像，记录来源／摘要；真实 PRoot 执行、退出、取消、PTY、CWD/文件和既有 Ubuntu 回归分别验证。

### P17：明确 JDK21 构建

本地与 verify/release/benchmark workflows 使用明确 JDK21 后，移除 foojay resolver 和 Daemon 的固定下载/vendor 配置。
沿既有 CI，不添加上游 daily-build；保持 Java/Kotlin target 和 Android desugaring 契约。完整门禁验证编译、lint、R8及双 ABI。

### P18：Claude 5.5 协议与注册

按官方 [Opus 5.5 迁移指南](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide) 与
[Sonnet 5.5](https://platform.claude.com/docs/en/models/sonnet-5-5/overview) 核验准确模型ID后注册，不删除 Claude 3 匹配。
精确 Opus／Sonnet 5.5 注册优先于旧族宽匹配，XHIGH 映射 xhigh，不误映射 max。Opus 不提供 OFF，已有 OFF 配置在 IO 前返回
`unsupported_reasoning_mode`；Sonnet OFF 仅发送 `thinking:{type:"between_tools"}`，UI说明工具之间仍可能思考。
其余支持的模式为 adaptive 并显示 summarized；保持空 thinking 的 signature 和 redacted，不以空文本判断可删除。
省略默认 sampling；显式非默认 temperature／top_p／top_k 和强制 any/tool choice 在 CustomBody 合并后的最终请求校验并报稳定错误，
top_p 的默认是 0.99 而非 1。旧族原行为不改变，不能静默换型号或更改用户指定语义。

按[思考回放协议](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking)，在现有不可编辑协议 metadata 中增加
nullable、version=1 的 Claude 回放证据：保存实际发出的 system／tools／messages 规范前缀摘要及每个 reasoning block 的位置／前缀摘要和原来源。
在真正的 tool-boundary 分组与最终 CustomBody 之后计算，排除协议允许变化的 cache_control 及非前缀请求参数；不得从当前 UI／Settings 补造。
回放逐块对已过滤的实际 wire 前缀重算，同时核验前一 thinking 的链关系，保留原序列的连续区间；
只有证据匹配才保留 thinking／redacted；缺证据或前缀改变只过滤本次请求投影，持久历史保持完整。
后续以过滤后前缀生成的新块仍可匹配，不能遇一次失效就永久删除全部后续块；不默认依赖 beta drop_block。
覆盖同一 assistant 多工具边界、多 thinking slot、空签名正文、cache_control 移动、摘要／压缩／编辑／fork／原来源变化、旧数据／备份恢复及已过滤块不复活。
使用会拒绝不符前缀的 wire fixture 验证；实际外部 Claude 服务另列环境证据，不把 mock 称作服务验证。

## 5. 数据与兼容决策

1. P09/P10/P18 只增加需要长期保存的历史事实；P09 保持外层 v2、内层 checkpoint v1，P10／P18 为显式 nullable 兼容字段。
   不把无来源旧数据“修复”为推测值；任一非法历史 payload 中止事务并保留可重试诊断。
2. P11/P12/P04 的 Settings 新字段默认分别为展开、更新时间、空 headers；由现有文档版本／migration 和 typed writer 管理，
   个人备份只保存个人偏好与用户定义，不能整体覆盖企业偏好。
3. P12 索引若新增，整批统一到下一 Room 版本及导出 schema；不得运行时临时建索引。
4. P03 resource 变化必须区分同一规范身份与不同授权资源；失配凭据显式要求重新授权，不能静默套用。
5. P08 工具名属于新增可选协议，原 assistant localTools 缺失时不启用；旧会话不依当前设置重解释历史结果。

## 7. 未引入项的重审条件

- 新型号／Interactions：官方可审计型号及端点材料，且存在现协议不能满足的本地消费目标；定义原始回放、终态、usage、旧配置和企业发布合同后重审。
- MCP 新协议／CIMD：确需新协议且验证自有 transport 的协商与通知生命周期；本批 SDK 显式停留 Legacy。CIMD另需 Pilot 自有正式 HTTPS metadata、临时回调端口兼容与部署责任。
- 记忆复制：明确个人局部运行记忆的显式选择、目标身份和跨 owner 部分失败／恢复 UX 后重审，不因复制共享定义自动复制所有域记忆。
- 媒体创作／S3素材外传：明确异步视频或独立创作会话需求、企业能力与上传隐私边界，再扩原配置／执行／GeneratedMedia owner；不是因为DB改动大而拒绝。
- 画板／Ink：选择原生草图或图片标注作为正式输入入口，明确触笔范围、原来源读取、取消及Artifact草稿交接后重审。
- 会话配置固定：明确会话 override 的产品目标、相对本域偏好及企业强制发布的优先级、恢复继承及失效引用UX；不标为本地已覆盖。
- Expressive／2025配色／UI模块：有本地整体设计或独立复用需求，并能保留窄屏、触控、自适应和企业只读投影时重审。
- 版本、品牌、开发skills和换行：按本地发行、任务工具或格式规范的独立需求处理，不随上游机械追平。

## 8. 独立计划复核与讨论
